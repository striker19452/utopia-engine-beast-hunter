# C · 猎场战图：全游戏视觉实施约定

方向已由用户采纳。基准画面为 `../interface-studies/review/atlas-interface.png`；交互参考为 `../interface-studies/index.html?concept=atlas`。早期参考页仅用于选型；正式游戏现已从根目录 `index.html` 接入 C，验证依据见本目录覆盖记录。

本约定用于约束完整游戏，不替代现有规则引擎。正式分支为 `codex/atlas-interface`。唯一色板与尺寸定义在 `../../css/atlas-tokens.css`；本目录 `tokens.css` 只导入该文件。`../../css/atlas.css` 统一所有正式组件，`../../js/atlas.js` 连接真实游戏状态、四个主界面和共用面板，`scene-coverage.json` 记录 21 组界面、117 个状态点的检查证据。

## 一、固定的视觉语言

C 的核心是“猎人在同一张战图旁处理整场狩猎”。背景是山谷地形，操作发生在地图旁的记录纸、图鉴和工作面板上。

| 项目 | 统一约定 | 允许变化 |
| --- | --- | --- |
| 材质 | 暖灰羊皮纸、深色墨迹、细墨线、低反光质感 | 纸面尺寸和内容密度随任务变化 |
| 色彩 | 朱红为主行动及危险/代价，苔绿为已知路径/完成，棕金为精工层级 | 雪峰青灰、海岸灰绿、裂痕铁锈色只用于小范围地区识别 |
| 字体 | 宋体标题、清晰的系统中文正文、Georgia 数值 | 正文 14px，说明 12px；手机不得靠缩小重要文字塞入桌面布局 |
| 美术 | 同一张地图、同一套素描图鉴、同一组线描图标 | 改变视窗、裁切和地区墨色；不另起一套写实角色渲染 |
| 交互 | 选中项、可放置位置、不可操作原因具有固定表现 | 按规则显示不同合法位置和代价 |
| 动效 | 标记、落骰、数字变化、面板切换的短反馈 | 尊重减少动态效果设置；无程序火焰、粒子爆团、长时间镜头晃动 |

颜色、间距、字阶、点击尺寸、动效时长由正式的 `css/atlas-tokens.css` 集中定义。功能模块不得另写一套色盘、按钮或弹窗；确有新需求时，先补公共组件，再用到页面。

图片生成只负责地图、图鉴等美术素材，不把整张界面生成成图片。重要文字、格子、按钮、状态仍以真实可操作的界面呈现。新素材必须与 C 的地图参考、画法、纸色、笔触与饱和度一致，并记录提示词与来源。

## 二、八组公共组件

1. **地图与全局状态骨架**：天数、事件/袭击标记、生命、怀疑、决心、当前猎场、村庄防线。打开工作面板后仍能辨识位置和风险；窄屏提供紧凑状态区。
2. **纸质工作面板**：共享标题、上下文、进度、正文、结果区、操作区和滚动规则。阅读、填格、战斗使用三个宽度级别；不是每个功能另造弹窗。
3. **骰子操作**：未掷、投掷中、可选、已选、已用、可修正、决心不足、幸运符可用/耗尽。数字与状态均有文字或形状提示。
4. **格子与落点**：空、已填、可落点、当前目标、不可落点、完成、故障。搜索六格、塔形、精炼格共享视觉原语，分别保留原有规则。
5. **数值与资源**：生命、怀疑、踪迹、物品次数、库存上限。相同信息位置和表现稳定；不只靠颜色识别危险。
6. **图鉴与信息行**：怪物素描、名称、生命、双方命中范围、性格、修正来源、材料需求、装备等级、计分行。
7. **提示与结果**：说明、获得、损失、警告、不可操作原因、确认和结算。主行动与继续/返回分层明确，不能把危险代价藏在装饰文案里。
8. **引导与操作反馈**：统一提示纸条、焦点、高亮、当前步骤和日志。与输入层级一致，不遮挡落点或确认按钮。

## 三、各场景如何延展，而不是全部长成同一页

| 场景族 | C 风格中的呈现 | 不可丢失的信息 |
| --- | --- | --- |
| 开场/读档 | 展开的战图与标题页、清晰的继续/新局操作 | 本地进度是否存在，重新开始的后果 |
| 主地图/猎场 | 当前 C 构图；地图标记与右侧追猎档案联动 | 三地进度、巢穴、巨兽生死、日期、全局风险 |
| 搜索/快速搜索 | 地图旁展开的搜索记录纸，骰子和六格为焦点 | 三轮骰子、当前选择、差值、结果表、剩余搜索与材料选择 |
| 遭遇/战斗/逃跑 | 同一地图背景压暗，展开更宽的战斗记录纸，原画素描占一侧 | 双方生命和命中范围、性格和装备修正、待确认骰子、物品、伤害与逃跑后果 |
| 建造/维修 | 村庄地图与塔形施工图，标出合法邻格和故障 | 原塔形、材料、合法落点、故障、维修和倒塌后果 |
| 锻造/合成 | 工匠记录纸；精炼格或配方表，延续相同骰子和材料组件 | 精炼计算、额外投入、标准/精工/失败、放弃代价 |
| 行囊/装备/图鉴 | 共用物品行、状态标记和图鉴布局 | 可用/已用、次数、甲壳剩余、等级、效果来源 |
| 长老/村庄/袭击 | 地图方向标记与防线/小屋变化，结果写入同一张记录纸 | 来袭方向、挡住或受损原因、鹰图腾、小屋损失、怀疑和追踪变化 |
| 休息/事件/日终 | 先展示成本和状态变化，再按原规则继续事件/袭击/怀疑结算 | 原有结算顺序，不能因视觉简化跳过步骤 |
| 教学/帮助/保存/失败反馈 | 同样的纸条、标题、按钮、说明层级 | 教学存档隔离、真实可用操作、保存和加载结果 |
| 胜利/三类失败 | 战图留作背景，展开结局手记与计分纸 | 正确失败原因、完整计分、重新开始 |

具体入口、状态列表与组件归属见 `scene-coverage.json`。正式面板通过同一份样式、语义变量和面板适配器统一；旧内联小字号与装饰 emoji 在展示层规范化，建造落点与精炼底色使用公共变量。规则计算仍在原模块中。搜索/战斗速查默认收起，可展开，并在本次会话中记住阅读偏好，让当前骰子与行动保持在前。

## 四、接入现有代码的方式

- 保留 `GameState`、掷骰、搜索计算、战斗顺序、建造邻接、锻造、计分与存档兼容逻辑。
- 新视觉在公共变量与组件层实现。现有 `UI.showModal` 是统一承载面板的接入口，应以向后兼容方式扩展场景标识、宽度和布局，再逐模块替换内部旧标记。
- 搜索、建造、锻造、战斗读取同一套骰子/数值/按钮组件；场景只提供内容、状态与合法操作。
- 每次替换后检查原来所有后续动作：关闭、取消、确认、继续搜索、日终、奖励选择、返回主地图。不得因为改用新面板而触发错误的关窗或重复结算。
- 保留 i18n 与教学的包装入口；不能用一个与正式逻辑脱离的演示状态机作为正式版。
- 文案、地图标记、游戏日志与全局 HUD 均取自真实状态。地图概念美术不应被误当作原规则中的精确地理图。

## 五、验证与持续维护

### 每个场景都要有证据

`scene-coverage.json` 中每个必要状态记录以下字段；布局检查与逐图人工审美验收分开标注：

- 已接入真实入口、公共组件与真实状态；
- 桌面与手机截图；涉及大量信息的场景增加平板截图；
- 所需交互检查及结果；
- 视觉检查结论、仍有的问题与对应截图。

现有 `../interface-studies/review/checks.json` 只能证明样稿的区域切换、掷骰与少量弹窗通过检查，不能作为战斗、锻造、事件或正式版全覆盖的证据。所有迁移前的基线图也只能证明现状，不能标记为新风格已验收。

### 必查的横向维度

- 桌面 1440px、平板 768px、手机 390px 与 320px；无横向溢出，触控目标至少 44px。
- 中文与英文长标题、长效果说明、日志变长、库存满、材料不足、按钮禁用。
- 默认、悬停、焦点、选中、按下、已用、错误/危险、结果反馈与素材未加载。
- 普通正文对比度至少 4.5:1；大字与非文字交互边界至少 3:1。重要状态不得只有颜色差异。
- 键盘遍历、面板焦点、合法的关闭/返回、再次进入后的状态、移动端滚动与底部操作。
- 减少动态效果；素材缺失仍保留名称、数值、格子和操作，不出现整块空白。
- 完整运行一条教学路径，以及搜索→遭遇→战斗→奖励→日终→事件/袭击→继续的真实流程；再覆盖锻造、建造/维修、合成和各结局。

### 收敛顺序

1. 统一变量、组件和地图骨架，冻结 C 的基准（已接入）。
2. 迁移搜索—战斗—日终链路，验证风格在连续场景中成立（由完整教学及规则回归验证）。
3. 覆盖建造/维修、锻造、合成、行囊、长老与物品恢复（已接入）。
4. 补齐教学、帮助、保存/加载、所有结局与边界状态（已接入）。
5. 按清单完成全局尺寸/语言/状态走查和现有规则回归，再宣布正式游戏整体完成。

**风格一致不能只靠规范文件保证。完成标准是：所有入口使用同一套组件，并且清单中的必要状态都有可复核的成图与实际流程检查。**

## 六、实际实现与复验入口

- 游戏入口：根目录 `index.html`，用静态 HTTP 服务打开；正式素材在 `assets/atlas/`，不依赖样稿目录。
- 新增场景：先复用 `css/atlas.css` 的组件，在 `AtlasUI.installContexts()` 登记场景名，再在 `scene-coverage.json` 增补状态，并为 `scripts/test_atlas_ui.js` 添加真实渲染入口。
- 自动检查：`node scripts/test_atlas_ui.js`（需要可用的 Playwright/Chromium；可用 `UEBH_BROWSER_EXECUTABLE` 指定浏览器）。输出 `outputs/atlas-review/scene-checks.json`、截图和 `index.html` 图集。截图使用真实渲染器与固定状态；不等同于每个分支都执行了一整局。
- 连续流程：`node scripts/test_tutorial.js` 覆盖搜索、战斗、日终、事件、手机、键盘、英文、退出恢复及存档隔离；新测试另外检查四页导航、真实读档往返、两次连续袭击、焦点恢复和素材缺失。
- 规则检查：`test_combat_order.js`、`test_combat_rewards.js`、`test_crab_plate.js`；静态检查为 `audit_i18n.js`、`audit_official_terms.js`、`audit_release.js`。
- 证据边界：自动检查确认溢出、图片、翻译残留与共享面板接入；代表画面另外逐组检查构图与层级。它们不能证明所有设备、浏览器、全部悬停组合或所有未来改动都无问题。

运行这些检查不会读写玩家实际浏览器的存档；测试使用独立浏览器上下文。`outputs/` 属于可再生成的本地验收产物，不纳入 Git。

## 七、掷骰同屏与帮助阅读（2026-10-18 修正）

掷骰流程使用紧凑操作台：当前进度、骰子、决心修正、幸运符、落点和结束/确认操作同屏呈现。搜索格始终按上、下两行排列，百／十／个位逐列对齐，连续放置两颗骰子时保持相同布局。建造及锻造直接点选可放置的骰子，取消同一数值的重复选骰区域；宽屏将塔形放在骰子旁，窄手机的西南塔也采用并排布局，保留 44px 点击尺寸。战斗常显大幅怪物素描、完整生命格与 HP 数值、实际与基础攻击范围以及修正来源；修正较多时，仅来源列表在块内滚动，骰子操作保持同屏。完整规则、修正来源、日志与机制解释仍可展开读取；连续修改或重掷只保留最新说明。

帮助窗口使用独立的正文阅读区，标题、紧凑的新手入口与关闭按钮不会参与正文滚动。“新手引导”默认折叠为 46px；展开后仍可重玩教学、开关首次提示和重看机制说明。

锻造选骰后直接点击原有精炼格空位，取消额外生成的落点格；同一组六格始终显示上方、下方和差值，已填入及已结算位置锁定。空位使用44px原生按钮，支持键盘操作；决心修改、幸运符重掷和负数清列规则保持原样。

回归脚本 `scripts/test_viewport_workflows.js` 使用真实按钮执行搜索修正/重掷/两骰落点、三种塔形、锻造、战斗、逃跑和帮助入口。147 个检查覆盖 1440×900、1280×720、662×706、390×844、320×740 中文，以及 662×706、320×740 英文；验证按钮和落点的完整矩形、中心未被遮挡、操作面板无需纵向滚动，并检查帮助正文占比。证据在 `outputs/viewport-workflows/checks.json`，此处的尺寸是已验证范围，并非对所有可能屏幕尺寸的承诺。教学回归同时验证可展开的解释文字以及折叠后的中英文重玩入口。

## 八、库存分隔与战斗信息恢复

材料按普通、稀有、怪物三组使用统一留白与连续横竖分隔线；共享污血仍跨三地列。合成道具使用衔接的行列边界，物品栏里的工具、消耗品和装备均保留逐项分隔线。

战斗恢复原始大幅画像、生命格与 HP 数字，战斗修正块始终可见；桌面并排放置修正与骰子，小屏紧凑排列。完整规则与历史日志另行展开。交叠命中按既有规则分别计数：同一骰子可同时命中双方，我方伤害先结算；怪物仍存活才结算其攻击。已补充同骰交叠、交叠击杀、装备造成范围交叠的回归检查，战斗顺序测试共 15 项通过。

本轮同屏检查增加装备、突然清醒、伏击与蟹甲同时存在的场景，合计 154 项通过；全部怪物/性格与塔形 48 组补充图和 480 组场景组合也通过。

## 九、材料与道具的配方连线

行囊默认展示配方关系，可切换回原来的库存清单。桌面保留紧凑材料库存侧栏，配方按可用宽度分2～3列；小屏使用1～2列。各配方的材料与实时库存紧邻对应产物，两条原料线汇入同一产物，避免跨越其他卡片。材料数字标注“库存 / 所需”，库存清单仍保留每种四格容量与三地来源。

配方来源必须是 `GAME_DATA.craftingRecipes` 与 `GAME_DATA.equipment`，不得独立维护一份连线表。当前共有7种合成道具、3件锻造装备、17条原料连接。实线表示该原料库存足够，虚线表示缺少；悬停、键盘聚焦可查看关系，点击固定高亮，使用“显示全部连线”取消。数量、道具持有状态、合成与锻造按钮继续读取真实 `GameState`，规则与消耗交由原有模块处理；日终结算和游戏结束时不能从新卡片绕过行动限制。

连线是不可交互的SVG装饰层，名称、数量和配方同时保留文本。`ResizeObserver`、字体加载和页面切换触发端点重算；缩放、换语言、合成后库存更新和桌面／手机切换都不能留下漂移的连接。

回归入口 `scripts/test_supply_links.js` 覆盖1440、1024、662、390和320像素宽度及中英文，检查17条边的实际端点、点击固定／键盘选择、库存清单往返、合成后的材料消耗与虚线更新，以及原始锻造入口。证据位于 `outputs/supply-links/`。

## 十、紧凑行囊

收紧标题、工具栏、说明栏与分组间距，将配方所需材料与操作按钮并排排布；库存来源、四格容量、数量、道具用途、所需材料、持有状态和所有使用／合成／锻造操作均保留。长文字与已持有道具的额外按钮自然换行，不使用截断、省略号或隐藏详情来压缩卡片。手机主要操作保留44px高度。进入行囊时缩小页首与状态栏的留白，切到其他页面恢复原尺寸。

同一1440×900窗口、相同库存的初始状态，行囊总高度由2348px缩至约747px（减少约68%）；首屏完整可见的合成道具由1种增至7种。662px窗口总高度由2475px降至约1008px；390px手机由2655px降至约1563px。数据来自实际渲染，并非按缩放截图推算。

回归同时检查10张道具／装备卡的名称、状态、用途和配方均存在且未被裁切，并覆盖全部道具已持有时额外使用按钮的换行。悬停仅预览高亮，点击后才更新固定选择说明，避免说明栏在按下与抬起之间移动按钮。连线在响应式重排、浏览器自动调整滚动位置后重新测量端点。密度对比与首屏截图位于 `outputs/supply-compact/`。

## 十一、调试工坊

`Game.showDebug()` 接入 `js/debug.js` 的独立编辑器，按核心与村庄、材料库存、猎场与巨兽、防御工事、装备等级分区。桌面使用固定侧栏，手机使用可横向滚动的分区导航；编辑区独立滚动，状态栏、反馈与完成按钮常驻。使用相同纸张、墨色、线条与图标，所有数值加减按钮保持44px。

直接输入、加减与批量操作均修改真实状态，再原位同步关联字段、上下限、分区计数与反馈；避免重建弹窗导致滚动和焦点丢失。修改塔状态时继续使用原来的完成、图腾、摧毁、故障数量规则。快捷操作包含满血、清零怀疑、决心+5、修复小屋、按组补满材料及批量装备等级；再次打开保留上次分区，Esc可关闭。

实际浏览器检查覆盖1440×900、1280×720、768×900、662×706、390×844、320×740及中英文，共30个分区画面和6次完整编辑流程。验证数值截断、材料上限、批量修改、区域标记、防御塔联动、输入焦点与滚动保持、关闭恢复、翻译残留和布局溢出。截图与报告位于 `outputs/debug-workshop/`；调试入口仍为独立开发工具。

## 十二、村庄场景

村庄采用与猎场相同的画面与档案布局。`VillageUI`在同一张3:2手绘底图上布置九间小屋、三座塔和议事厅／作坊／营地，建筑本身就是可点击的入口。住宅使用完好／废墟透明图集；防御塔使用未完工／完工／废墟透明图集，并同步故障与图腾标记。图像、位置和提示词记录在 `assets/atlas/village-art.json`。

原有的塔格、塔状态、鹰图腾安装按钮、小屋清单与规则、长老姓名／奖励／审批标记移入所选建筑档案，保持真实状态与原有结算。塔连接材料选择，作坊连接锻造／合成，营地连接休息确认；查看建筑不会推进天数或领取奖励，日终待结算与游戏结束时不能从场景绕过行动限制。

窄屏场景保留760px绘制宽度与至少44px的建筑点击区域，可触摸横向浏览，亦可通过左右箭头和地点导航跳转；建筑选中后显示详情。名称标签在画面边缘或标题后方自动隐藏，建筑仍保留独立可访问名称。村庄页的全局操作栏随页面排列，避免遮挡场景。素材缺失时文字、建筑选择及服务入口仍可用。

`scripts/test_village_scene.js`覆盖1440×1050、1280×900、768×900、662×706、390×844、320×740的中英文，共24个画面和6组实际操作：15个建筑热点、建造／锻造／合成／休息入口、图腾安装与消耗、废墟切换、统计、语言往返、结算期间禁用、重开恢复、键盘及缺图回退。证据在 `outputs/village-scene/`；原掷骰同屏与帮助的154项检查也通过。
